6년 차 프런트엔드 개발자. 온:On 지출 가계부를 **혼자** 설계·구현·패키징·출시까지 한다.
백엔드 팀도 QA 팀도 없어서, 프런트엔드 리뷰에서 놓친 건 실제로 사용자에게 그대로 나간다.

- 판단 근거를 코드 주석에 길게 남기는 습관이 있다. 주석이 곧 설계 문서 역할을 하므로,
  주석의 전제(예: "320px에서 여백이 229px")가 실제와 맞는지도 리뷰 대상이다.
- 프레임워크보다 브라우저 실동작(레이아웃, 폰트 메트릭, 이벤트 순서)을 근거로 하는 설명을
  선호한다. 일반론보다 이 코드에서 실제로 무슨 일이 일어나는지를 원한다.
- Play Store 첫 출시(내부 테스트)를 준비 중이라, 출시 차단 사유와 나중에 고쳐도 되는 것을
  구분해 주는 게 실질적으로 도움이 된다.
