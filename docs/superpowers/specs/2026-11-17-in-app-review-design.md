# 앱 안에서 Play 리뷰 요청 — 설계 (작은 변경)

2026-11-17 대화에서 정했다.

## 왜

스토어에 별점이 쌓이면 새 사용자에게 더 잘 보인다. 앱을 충분히 써 본 사람에게 한 번만, 조르지 않고 묻는다.

## 하는 것

- **구글 Play 인앱 리뷰 창을 딱 한 번 띄운다.** 조건: 처음 쓴 날부터 7일이 지났고, 방금 새 기록을 추가했다.
  - "처음 쓴 날" = 직접 적은 기록(`importId` 없는 지출) 중 가장 이른 `createdAt`. 가져온 기록은 세지 않는다 —
    3천 건을 가져오자마자 뜨면 안 된다. 백업에서 복원한 기록은 원래 `createdAt`을 들고 오므로 오래 쓴 사람으로 본다.
  - 이미 쓰고 있는 사람은 업데이트 뒤 첫 기록 추가 때, 새로 깐 사람은 일주일 뒤 첫 기록 추가 때 뜬다.
  - "새 기록 추가" = 입력 탭의 저장, 달력 시트의 새 지출·새 할부 저장. 고치기·할부 다시 나누기는 아니다.
  - 한 번 부르면 폰(`localStorage`)에 표시를 남기고 다시는 부르지 않는다. 평가했는지 앱은 알 수 없다 — 구글이
    일부러 알려주지 않는다. 그래서 "평가한 사람만 다시 안 나오게" 대신 "한 번 띄우면 끝"이다.
- **설정 › 정보에 "Play 스토어에서 평가하기" 줄.** 스토어 페이지를 연다. 창을 놓친 사람이 나중에 평가할 길.
  리뷰 창을 여는 버튼은 두지 않는다 — 구글이 한 달 안에 여러 번 부르면 창을 안 띄우므로 눌러도 아무 일 없는
  버튼이 될 수 있고, 구글 지침도 버튼은 스토어로 보내라고 한다.
- 웹 버전에서는 둘 다 없다.

## 안 하는 것 (구글 지침)

- 창 앞뒤로 앱이 묻지 않는다: "마음에 드세요?", "별 5개 주실래요?" 같은 문구 없음.
- 구글 창의 모양을 바꾸거나 위에 무엇을 덮지 않는다. 띄운 뒤 코드로 닫지 않는다.
- 별점에 보상을 주지 않는다.

## 만드는 법

- Play 리뷰 라이브러리(`com.google.android.play:review`)를 넣고, 앱과 잇는 짧은 Capacitor 플러그인을
  `android/app` 안에 직접 쓴다(외부 npm 플러그인 안 씀). R8을 켜도 Capacitor가 `@CapacitorPlugin` 클래스를 남긴다.
- 리뷰를 물을지 정하는 판단은 순수 함수로 두고 단위 테스트한다.
- 리뷰 창은 저장 직후 "저장했어!" 토스트가 보일 만큼 짧게 기다렸다 띄운다.

## 확인

- 리뷰 창은 Play에서 받은 앱에서만 제대로 뜬다 → v26 내부 테스트로 폰에서 확인. R8 켜는 것도 같이 확인.
- 개발자 본인 폰에도 뜬다. 자기 앱에 별점을 주는 건 정책 위반이라 닫는다.
- 데이터 보안 양식: 별점·리뷰는 Play가 직접 받고 앱은 보지 않는다. 새로 신고할 수집 항목은 없을 것으로 보지만
  제출 전에 한 번 확인한다.

## 빌더에게 남긴 것
