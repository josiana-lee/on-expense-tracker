# on-expense-tracker 디자인 브리프

> 지출 기록에 특화된 개인 가계부 앱. Weple Wallet(위플 가계부)을 오마주하되,
> **"앱을 열자마자 3초 안에 지출 입력이 끝나는 것"**이 핵심 차별점.

## 1. 컨셉 요약

- 기존 가계부 앱은 달력/리스트가 첫 화면 → 입력까지 2~3번 탭이 필요함
- 우리 앱은 **첫 화면 = 입력 화면**. 열자마자 금액 치고, 카테고리 찍고, 결제수단 찍고, 추가! 끝.
- 톤앤매너: 위플 가계부처럼 밝고 파스텔톤의 컬러풀한 원형 카테고리 아이콘, 깔끔한 흰 배경. 단, 광고 없는 미니멀한 화면.
- 플랫폼: 모바일 앱, **Android 우선 출시**
- 기술 스택: **React 19 + Vite + TypeScript, PWA**. 시안이 이미 HTML/CSS로 나와 있어 애니메이션까지 그대로 옮겨지는 점, 로컬 전용 앱이라 네이티브 API 의존이 없는 점이 결정 이유. Play Store 출시 시점에 Capacitor로 감싼다
- 디자인 기준 해상도: 412×892 (Android), 단 iOS 확장을 막는 플랫폼 종속 UX는 피할 것

## 2. 메인 화면 (= 퀵 입력 화면)

위에서 아래 순서로:

### 2-1. 상단: 실시간 날짜/시간
- 오늘 날짜와 현재 시간이 **크게, 실시간으로** 표시 (예: `8월 2일 토요일` / `16:42`)
- 시간은 분 단위로 실시간 갱신. 화면의 히어로 역할 — 타이포그래피가 큰 비중
- (기록 시각이 이 시간으로 자동 저장된다는 것을 암시하는 UI)

### 2-2. 금액 입력
- 날짜/시간 바로 아래, 탭 없이 바로 입력 가능한 큰 금액 필드
- 원화 기준, 천 단위 콤마 자동 표기, 커스텀 숫자 키패드 (시스템 키보드 대신)
- 금액 입력 필드가 화면 진입 시 자동 포커스

### 2-3. 카테고리 선택 (아이콘)
- 지출 카테고리를 원형 컬러 아이콘 그리드로 표시 (위플 스타일: 식비🍽, 간식🍔, 생필품🛒, 교통비🚌, 의류👕, 문화생활📷, 미용🛁, 의료/건강⚕, 교육📖, 통신비📱, 경조사🎁, 기타 등)
- **핵심 인터랙션**: 아이콘을 탭하면 → 그 아이콘 위치에서 화면 가운데로 **"쇽!" 하고 튀어나오듯** 선택 확인 컴포넌트가 확대되며 등장 (탭한 지점이 애니메이션의 origin)
- 가운데 뜬 컴포넌트에서 세부 아이콘/메모를 바로 선택·입력 가능

### 2-4. 결제수단 선택
- 카테고리 아래에 가로 스크롤 칩(chip) 형태로: 저장된 카드 목록 + 현금
- 예: `현금` `현대카드` `삼성카드` `롯데카드` `국민카드` `농협카드` `체크카드`
- 하나 선택 시 선택 상태가 명확히 표시 (컬러 채움 + 살짝 튀는 스프링 애니메이션)

### 2-5. 추가 버튼
- 화면 하단 고정, 큰 CTA 버튼 `추가!`
- 탭하면 입력 내용이 저장되면서 만족스러운 마이크로 인터랙션 (버튼에서 체크가 쇽 튀어나오거나, 금액이 날아가서 저장되는 연출)
- 저장 후 필드가 리셋되어 연속 입력 가능

## 3. 하단 탭바 (메인 탭 4개 + 입력)

| 탭 | 내용 |
|---|---|
| 전체 달력 | 월 달력에 일별 지출 합계 표시, 날짜 탭하면 그날 지출 리스트 (위플 달력 뷰 오마주) |
| 예산 | 월간/주간 예산 설정 및 진행률. 주차별 지출 합계 리스트 + 예산 초과 경고 |
| 총 자산 | 현금/카드별 잔액·사용액 요약 (위플 자산 탭 오마주: 총 자산, 내 계좌, 내 카드, 이번 달 결제/미결제) |
| 설정 | 카테고리 관리(지출/입금), 카드 관리(신용/체크), 반복 지출, 월 시작일, 주 시작요일, 다크모드, 알람, CSV 내보내기, 백업 |

- 퀵 입력 화면은 탭바의 가운데 or 첫 번째 자리 (앱 실행 시 기본 진입점)
- 탭 전환에도 부드러운 전환 애니메이션

## 4. 애니메이션 원칙 (전체 공통) ⭐

이 앱의 아이덴티티. 모든 팝업/컴포넌트 등장은:

1. **탭한 요소가 애니메이션의 출발점** — 화면 정중앙에서 페이드인 X. 사용자가 누른 아이콘/버튼 위치에서 스케일업하며 "쇽!" 하고 튀어나옴
2. 스프링(탄성) 커브 사용 — 밋밋한 ease-in-out보다 살짝 오버슈트되는 탄성감
3. 닫힐 때는 역재생으로 원래 아이콘 위치로 빨려 들어감
4. 지속시간 200~350ms, 빠르고 경쾌하게
5. 카테고리 선택, 결제수단 선택, 탭 전환, 추가 완료 피드백 모두 동일 원칙 적용

## 5. 디자인 산출물 요청 사항

클로드디자인에게 요청할 것:

1. **메인 퀵 입력 화면** (최우선) — 날짜/시간 히어로 + 금액 + 카테고리 그리드 + 결제수단 칩 + 추가 버튼의 레이아웃
2. 카테고리 탭 시 가운데로 튀어나오는 **선택 컴포넌트의 모션 시안** (before/after 프레임)
3. 하단 탭바 및 4개 서브 화면의 와이어프레임 (달력 / 예산 / 자산 / 설정)
4. 컬러 팔레트 (파스텔톤 카테고리 컬러 12종 + 메인 브랜드 컬러) 및 타이포 스케일 (특히 시간/금액 대형 숫자)
5. 라이트 모드 우선, 다크 모드 확장 고려

## 5-1. 열어둔 UX 질문 — 저장 버튼이 두 개인 문제

입력 화면에 `추가!`가 두 곳에 있다.

- **팝업 안의 `추가!`** — 고른 카테고리로 저장한다. 실제 주 경로
- **화면 하단의 `추가!`** — 카테고리 없이 `기타`로 저장한다

이름이 같은데 하는 일이 다르고, 시각적으로는 하단 버튼이 훨씬 크고 강조돼 있다. 즉 **가장 눈에 띄는 버튼이 가장 질 낮은 데이터(미분류)를 만든다.** `기타` 아이콘이 이미 그리드 안에 있어서 하단 버튼이 아끼는 것은 탭 1회뿐이다.

검토한 안:
1. 하단 버튼 제거 + 금액 입력 시 그리드 위에 `어디에 썼어?` 안내 — 버튼이 하나로 정리되고 78px가 빈다
2. 하단 버튼 유지 + 이름 변경 (`기타로 빠르게 추가`)
3. 유지

**부분 반영 (2026-08-02).** 팝업 버튼을 `추가!` → **`입력 완료`**로 이름만 바꿨다. "카테고리를 골라 완결한다"는 느낌이 하단의 범용 `추가!`와 구분되지만, 하단 버튼 자체를 없앨지·이름을 바꿀지는 여전히 미정이다. 달력 탭을 며칠 써보고 미분류(`기타`) 기록이 실제로 얼마나 쌓이는지를 보고 최종 결정한다.

## 6. 수익화 · 데이터 보관

- **현재 스코프는 광고 단일 티어.** Pro(광고 제거 유료) 버전은 나중에 검토하되, 지금은 설계·구현에서 제외한다
- **광고 위치: 입력 화면 "오늘 기록" 카드 바로 아래**, `추가!` 버튼과는 간격을 둔다
  - `추가!` 버튼 바로 밑은 배제했다. 반복해서 누르는 주 CTA에 광고가 붙으면 오터치가 나고, 이는 사용자 경험뿐 아니라 AdMob 무효 트래픽 정책상으로도 위험하다
  - 배너는 고정 높이(약 50~60px)로 잡고, 줄어드는 만큼은 "오늘 기록" 목록이 흡수한다. 시계·금액·카테고리 그리드는 절대 밀리지 않게 한다
- **백업은 필수 기능.** 기기를 바꿔도 데이터가 살아남아야 함
  - **채널은 3개로 확정 (2026-08-03).** iCloud, CSV, 이메일. 시안엔 Dropbox도 있었지만 뺀다
  - CSV는 구현 완료 (`src/db/exportCsv.ts`) — 내보내기 전용, 복원 경로 아님. UTF-8 BOM·CSV 인젝션 방지 확인됨
  - iCloud·이메일 백업은 아직 미착수. Android 우선 출시인데 iCloud는 iOS 생태계 — Capacitor 진영에서 어떻게 붙일지(iOS 확장 시점에 iCloud, 이메일은 지금도 가능 — 백업 파일을 메일 첨부로 보내는 형태) 착수 시 다시 설계
- ⚠️ 시안의 설정 화면 푸터가 `on-expense-tracker v0.1 · 광고 없음`으로 되어 있음 → 광고가 들어가므로 이 문구는 수정 필요
- ⚠️ 포장 방식은 광고 SDK 선택과 묶여 있다 (출시 직전에 결정)
  - **TWA + AdSense**: Chrome과 저장소를 공유해 웹→앱 데이터 이관 문제가 없다. 대신 웹 광고라 단가가 낮다
  - **Capacitor + AdMob**: 앱 광고라 단가가 낫지만 웹 PWA 사용자의 데이터가 넘어가지 않는다
  - 결론이 나기 전까지 **웹 버전을 공개 배포하지 않는다.** 사용자가 쌓인 뒤에 Capacitor로 가면 전원이 데이터를 잃는다

## 7. 참고 (오마주 원본: Weple Wallet)

- 원형 컬러 카테고리 아이콘, 일별 지출이 표기되는 달력, 주차별 예산 리스트, 자산 탭 구조를 참고
- 단, 원본의 광고 배너 / 유료 잠금(탭바 편집 광고) UX는 배제
- 원본과 달리 첫 화면이 달력이 아니라 **입력**이라는 점이 가장 큰 구조 차이
