# on-expense-tracker 디자인 브리프

> 지출 기록에 특화된 개인 가계부 앱. Weple Wallet(위플 가계부)을 오마주하되,
> **"앱을 열자마자 3초 안에 지출 입력이 끝나는 것"**이 핵심 차별점.

## 1. 컨셉 요약

- 기존 가계부 앱은 달력/리스트가 첫 화면 → 입력까지 2~3번 탭이 필요함
- 우리 앱은 **첫 화면 = 입력 화면**. 열자마자 금액 치고, 카테고리 찍고, 결제수단 찍고, 추가! 끝.
- 톤앤매너: 위플 가계부처럼 밝고 파스텔톤의 컬러풀한 원형 카테고리 아이콘, 깔끔한 흰 배경. 단, 광고 없는 미니멀한 화면.
- 플랫폼: 모바일 앱, **Android 우선 출시**
- 기술 스택: **React 19 + Vite + TypeScript, PWA**. 시안이 이미 HTML/CSS로 나와 있어 애니메이션까지 그대로 옮겨지는 점, 로컬 전용 앱이라 네이티브 API 의존이 없는 점이 결정 이유. Play Store 출시 시점에 Capacitor로 감싼다
- 디자인 기준 해상도: 412×892 (Android), 단 iOS 확장을 막는 플랫폼 종속 UX는 피할 것

## 2. 메인 화면 (= 퀵 입력 화면)

위에서 아래 순서로:

### 2-1. 상단: 실시간 날짜/시간
- 오늘 날짜와 현재 시간이 **크게, 실시간으로** 표시 (예: `8월 2일 토요일` / `16:42`)
- 시간은 분 단위로 실시간 갱신. 화면의 히어로 역할 — 타이포그래피가 큰 비중
- (기록 시각이 이 시간으로 자동 저장된다는 것을 암시하는 UI)

### 2-2. 금액 입력
- 날짜/시간 바로 아래, 탭 없이 바로 입력 가능한 큰 금액 필드
- 원화 기준, 천 단위 콤마 자동 표기, 커스텀 숫자 키패드 (시스템 키보드 대신)
- 금액 입력 필드가 화면 진입 시 자동 포커스

### 2-3. 카테고리 선택 (아이콘)
- 지출 카테고리를 원형 컬러 아이콘 그리드로 표시 (위플 스타일: 식비🍽, 간식🍔, 생필품🛒, 교통비🚌, 의류👕, 문화생활📷, 미용🛁, 의료/건강⚕, 교육📖, 통신비📱, 경조사🎁, 기타 등)
- **핵심 인터랙션**: 아이콘을 탭하면 → 그 아이콘 위치에서 화면 가운데로 **"쇽!" 하고 튀어나오듯** 선택 확인 컴포넌트가 확대되며 등장 (탭한 지점이 애니메이션의 origin)
- 가운데 뜬 컴포넌트에서 세부 아이콘/메모를 바로 선택·입력 가능

### 2-4. 결제수단 선택
- 카테고리 아래에 가로 스크롤 칩(chip) 형태로: 저장된 카드 목록 + 현금
- 예: `현금` `현대카드` `삼성카드` `롯데카드` `국민카드` `농협카드` `체크카드`
- 하나 선택 시 선택 상태가 명확히 표시 (컬러 채움 + 살짝 튀는 스프링 애니메이션)

### 2-5. 추가 버튼
- 화면 하단 고정, 큰 CTA 버튼 `추가!`
- 탭하면 입력 내용이 저장되면서 만족스러운 마이크로 인터랙션 (버튼에서 체크가 쇽 튀어나오거나, 금액이 날아가서 저장되는 연출)
- 저장 후 필드가 리셋되어 연속 입력 가능

## 3. 하단 탭바 (메인 탭 4개 + 입력)

| 탭 | 내용 |
|---|---|
| 전체 달력 | 월 달력에 일별 지출 합계 표시, 날짜 탭하면 그날 지출 리스트 (위플 달력 뷰 오마주) |
| 예산 | 월간/주간 예산 설정 및 진행률. 주차별 지출 합계 리스트 + 예산 초과 경고 |
| 총 자산 | 현금/카드별 잔액·사용액 요약 (위플 자산 탭 오마주: 총 자산, 내 계좌, 내 카드, 이번 달 결제/미결제) |
| 설정 | 카테고리 관리(지출/입금), 카드 관리(신용/체크), 반복 지출, 월 시작일, 주 시작요일, 다크모드, 알람, CSV 내보내기, 백업 |

- 퀵 입력 화면은 탭바의 가운데 or 첫 번째 자리 (앱 실행 시 기본 진입점)
- 탭 전환에도 부드러운 전환 애니메이션

## 4. 애니메이션 원칙 (전체 공통) ⭐

이 앱의 아이덴티티. 모든 팝업/컴포넌트 등장은:

1. **탭한 요소가 애니메이션의 출발점** — 화면 정중앙에서 페이드인 X. 사용자가 누른 아이콘/버튼 위치에서 스케일업하며 "쇽!" 하고 튀어나옴
2. 스프링(탄성) 커브 사용 — 밋밋한 ease-in-out보다 살짝 오버슈트되는 탄성감
3. 닫힐 때는 역재생으로 원래 아이콘 위치로 빨려 들어감
4. 지속시간 200~350ms, 빠르고 경쾌하게
5. 카테고리 선택, 결제수단 선택, 탭 전환, 추가 완료 피드백 모두 동일 원칙 적용

## 5. 디자인 산출물 요청 사항

클로드디자인에게 요청할 것:

1. **메인 퀵 입력 화면** (최우선) — 날짜/시간 히어로 + 금액 + 카테고리 그리드 + 결제수단 칩 + 추가 버튼의 레이아웃
2. 카테고리 탭 시 가운데로 튀어나오는 **선택 컴포넌트의 모션 시안** (before/after 프레임)
3. 하단 탭바 및 4개 서브 화면의 와이어프레임 (달력 / 예산 / 자산 / 설정)
4. 컬러 팔레트 (파스텔톤 카테고리 컬러 12종 + 메인 브랜드 컬러) 및 타이포 스케일 (특히 시간/금액 대형 숫자)
5. 라이트 모드 우선, 다크 모드 확장 고려

## 5-1. 열어둔 UX 질문 — 저장 버튼이 두 개인 문제

입력 화면에 `추가!`가 두 곳에 있다.

- **팝업 안의 `추가!`** — 고른 카테고리로 저장한다. 실제 주 경로
- **화면 하단의 `추가!`** — 카테고리 없이 `기타`로 저장한다

이름이 같은데 하는 일이 다르고, 시각적으로는 하단 버튼이 훨씬 크고 강조돼 있다. 즉 **가장 눈에 띄는 버튼이 가장 질 낮은 데이터(미분류)를 만든다.** `기타` 아이콘이 이미 그리드 안에 있어서 하단 버튼이 아끼는 것은 탭 1회뿐이다.

검토한 안:
1. 하단 버튼 제거 + 금액 입력 시 그리드 위에 `어디에 썼어?` 안내 — 버튼이 하나로 정리되고 78px가 빈다
2. 하단 버튼 유지 + 이름 변경 (`기타로 빠르게 추가`)
3. 유지

**부분 반영 (2026-08-02).** 팝업 버튼을 `추가!` → **`입력 완료`**로 이름만 바꿨다. "카테고리를 골라 완결한다"는 느낌이 하단의 범용 `추가!`와 구분되지만, 하단 버튼 자체를 없앨지·이름을 바꿀지는 여전히 미정이다. 달력 탭을 며칠 써보고 미분류(`기타`) 기록이 실제로 얼마나 쌓이는지를 보고 최종 결정한다.

## 6. 수익화 · 데이터 보관

- **현재 스코프는 광고 단일 티어.** Pro(광고 제거 유료) 버전은 나중에 검토하되, 지금은 설계·구현에서 제외한다
- **광고 위치: 입력 화면 "오늘 기록" 카드 바로 아래**, `추가!` 버튼과는 간격을 둔다
  - `추가!` 버튼 바로 밑은 배제했다. 반복해서 누르는 주 CTA에 광고가 붙으면 오터치가 나고, 이는 사용자 경험뿐 아니라 AdMob 무효 트래픽 정책상으로도 위험하다
  - 배너는 고정 높이(약 50~60px)로 잡고, 줄어드는 만큼은 "오늘 기록" 목록이 흡수한다. 시계·금액·카테고리 그리드는 절대 밀리지 않게 한다
- **백업은 필수 기능.** 기기를 바꿔도 데이터가 살아남아야 함
  - **채널은 3개로 확정 (2026-08-03).** iCloud, CSV, 이메일. 시안엔 Dropbox도 있었지만 뺀다
  - CSV는 구현 완료 (`src/db/exportCsv.ts`) — 내보내기 전용, 복원 경로 아님. UTF-8 BOM·CSV 인젝션 방지 확인됨
  - 이메일 백업 구현 완료 (`emailBackup()`) — 공유 시트로 백업 JSON을 넘기고 메일 앱을 고르게 함, 공유 미지원 환경은 다운로드+mailto 폴백
  - 아이클라우드 백업 구현 완료 (`icloudBackup()`, 2026-08-03) — 웹 PWA에서는 CloudKit에 접근할 수 없어 진짜 자동 동기화가 아니라, 이메일 백업과 동일하게 공유 시트를 띄우고 사용자가 "파일에 저장" → iCloud Drive를 직접 고르게 하는 방식. Capacitor 전환 시 네이티브 iOS 플러그인으로 다시 설계 필요
  - 백업 복원 구현 완료 (`db/restore.ts`, 2026-08-03) — data-model.md §7-1 규칙 그대로: formatVersion 검사 → Zod로 테이블별 행 단위 검증(깨진 행만 건너뜀) → 복원 전 현재 데이터 자동 다운로드(안전망) → 단일 트랜잭션 clear+bulkPut 전체 교체. 병합은 MVP 범위 밖. 설정 화면 "백업 파일 복원하기"에서 파일 선택 → 건수 미리보기 확인 → 확인 시트를 거쳐 실행
  - 백업 리마인더 구현 완료 (`useBackupOverdue`, 2026-08-03) — data-model.md §7-1 B. `meta.lastBackupAt`을 iCloud/이메일 백업(복원 가능한 채널만, CSV 제외) 성공 시 갱신하고, 14일 지나면 설정 탭 아이콘에 점 배지 + 설정 화면에 경고 배너. 최초 설치 후 아직 한 번도 백업 안 했으면 `meta.installedAt` 기준으로 유예 기간을 준다
- **반복 지출 구현 완료** (`db/recurring.ts`, 2026-08-03) — 설정 하위 screen으로 결정 (하단 탭바 추가 아님). 사용자가 요일/월중일/월을 직접 고르지 않고 시작일 하나만 고르면 그 날짜에서 패턴(요일/일/월)을 자동으로 뽑아낸다
  - `mode: 'auto'`는 앱 부팅마다(`bootstrap()` 안에서) 밀린 회차를 전부 자동 기록. `mode: 'remind'`는 부팅 시 아무것도 안 만들고 목록에 "기록 대기 중"으로만 보여주다가 사용자가 "지금 기록하기"를 눌러야 한 회차씩 기록됨 — 알림 인프라 없이도 remind 모드가 실질적 기능을 갖도록 한 설계
  - 멱등성은 `expenses`의 `&[recurringRuleId+occurrenceDate]` 유니크 인덱스로 보장 (data-model.md §반복 지출과 동일). 규칙 수정이 시작일 기준으로 스케줄을 리셋해도, 이미 만들어진 회차는 인덱스가 막아줘서 안전
  - 규칙 삭제는 규칙 행만 지움 (이미 생성된 지출 기록은 그대로 남음) — 카테고리처럼 과거 기록이 참조하는 값이 화면에 다시 표시되는 구조가 아니라서 소프트 삭제가 필요 없음
- **카드 관리 구현 완료** (`db/paymentMethods.ts`, 2026-08-03) — Weple 시안 대비 갭 점검(2026-08-03)에서 나온 항목. 이전엔 "카드 관리"라는 이름과 달리 결제 주기 설정만 가능하고 프리셋 카드 5장이 고정이었음
  - 자산 탭 "내 카드"에 "+ 카드 추가" 추가. 카드 이름을 자유 입력(예: "농협 체크카드")으로 받아서 프리셋에 없는 은행/카드도 표현 가능. 신용/체크 종류 선택 + 결제일/사용기간 시작일을 한 화면에서 같이 설정
  - 카드 삭제는 카테고리와 동일하게 하드 삭제가 아니라 `archived: true` — `expenses.paymentMethodId`가 과거 기록에 직접 남아있어서, 지우면 옛날 기록이 참조를 잃는다. `useCatalog()`의 `paymentById`가 이미 archived 포함 전체 맵이라 별도 작업 없이 과거 기록엔 카드명이 그대로 보임 (직접 확인함)
  - 프리셋 카드를 5장→3장(현대/삼성/체크)으로 줄임 — 이제 사용자가 직접 추가할 수 있으니 안 쓰는 은행 카드를 미리 심어둘 이유가 없음. 기존 설치엔 영향 없음(빈 테이블일 때만 시딩)
  - 카드 순서 바꾸기 추가 (2026-08-03) — 카테고리 관리엔 아직 없는 기능이지만 카드만 먼저 만들기로 함(사용자 선택). 드래그 대신 위/아래 화살표 버튼으로: 표시 순서(sortOrder)를 인접한 카드와 맞바꾸는 방식이라 전체 리스트를 다시 매길 필요가 없음. 자산 탭 카드 행이 버튼 하나에서 "탭하면 수정" 버튼 + 화살표 두 개로 구조가 바뀜(계좌 행은 그대로 버튼 하나)
  - 예산 초과 알림(토스트/배지)은 만들지 않기로 결정 (2026-08-03) — 예산 탭에서 초과 여부를 확인하는 지금 방식으로 충분하다고 판단, `budgetAlerts` 테이블은 스키마만 있고 미사용 상태 유지
- **카테고리별 예산 구현 완료** (2026-08-03) — 새 탭이 아니라 기존 예산 탭에 추가된 섹션. `BudgetRecord.scope: 'category'`는 스키마엔 처음부터 있었지만 `'total'`만 실제로 쓰이고 있었음
  - "카테고리별 예산" 섹션에 "+ 카테고리 예산 추가" — 카테고리 하나 고르고 금액 입력하면 그 달 지출 중 해당 카테고리 지출만 따로 집계해서 진행률 바로 보여줌. 이미 예산이 잡힌 카테고리는 추가 화면 선택지에서 제외해서 같은 달에 중복 예산이 안 생기게 막음
  - 주차별 분할은 전체 예산에만 있고 카테고리별 예산엔 없음 — 전체 예산이 이미 주간 페이싱을 보여주므로 카테고리별로 또 나누는 건 과한 것으로 판단
  - 삭제는 참조하는 레코드가 없어서(카테고리·카드와 달리 예산을 가리키는 다른 테이블이 없음) 소프트 삭제 없이 그냥 지움
- 설정 화면 푸터 정리 완료 (2026-08-04) — 시안의 `on-expense-tracker v0.1 · 광고 없음`을 앱 이름·버전·저작권 표기로 교체. 값은 `src/data/appInfo.ts` 한 곳에 모으고, 비어 있는 항목은 해당 줄 자체를 렌더링하지 않아 미기입 링크가 출시본에 나가지 않게 함

- **포장 방식 확정: Capacitor + 카카오 애드핏(앱 지면)** (2026-08-04)

  **TWA는 검토 끝에 성립하지 않는다.** TWA는 앱이 곧 웹사이트라서 HTTPS 도메인에 공개 호스팅이 필수인데, 이 앱은 **웹으로 배포하지 않고 앱으로만 출시**하기로 했다. Capacitor는 파일이 APK 안에 들어가므로 공개되는 것이 없다.

  브리프가 원래 TWA의 장점으로 꼽았던 "웹→앱 데이터 이관 문제 없음"은 **이관할 사용자가 없어서 무의미해졌다.** 결정 시점까지 웹을 배포하지 않은 덕분이고, 이는 data-model.md §7-0이 세 번째 선택지로 적어둔 경로 그대로다.

  광고는 AdMob이 아니라 **카카오 애드핏**으로 간다. 심사가 이미 완료되어 있고, 웹/앱 지면을 따로 발급하므로 "AdSense는 앱에 못 넣는다"는 제약 자체가 없다. 앱으로만 낼 것이므로 **앱 지면**을 쓴다.

  이 선택으로 같이 정해지는 것들:
  - **데이터 서버는 어느 쪽이든 필요 없었고, 정적 호스팅도 필요 없어졌다.** 기록은 전부 기기 IndexedDB에 있고 백업은 OS 공유 시트로 나간다
  - **알림을 제대로 고칠 수 있게 된다.** 현재 리마인더는 `setTimeout` 기반이라 앱이 꺼지면 울리지 않고, 설정 화면에 그 한계를 안내 문구로 적어 두었다. Capacitor의 LocalNotifications로 바꾸면 서버 없이 해결되고 그 문구도 지울 수 있다. TWA로 갔다면 Web Push(=서버)가 필요해 그대로 남았을 문제다
  - **저장소는 TWA보다 불리하다.** Capacitor WebView 저장소는 휘발 가능으로 간주된다(data-model.md §7-0). `navigator.storage.persist()`는 이미 부팅 시 호출하고 있고, 백업 3채널·복원·14일 리마인더 배지가 그 대비다

  **착수 전 확인이 필요한 것:** 애드핏 앱 SDK는 네이티브라 Capacitor에서 쓰려면 브리지가 필요하다. 공식 플러그인이 있는지 확인하고, 없으면 (a) 소형 커스텀 플러그인을 만들거나 (b) 배너를 WebView 바깥 네이티브 레이아웃에 두는 방식을 택한다. (b)를 고르면 지금 웹 레이아웃 안에 잡아둔 52px `AdSlot` 자리는 없애고 그만큼 WebView 높이가 줄어드는 형태가 된다
